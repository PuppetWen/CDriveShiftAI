## 已确认的问题及修复

| 范围 | 原问题 | 修复后的行为 |
| --- | --- | --- |
| 文件完整性 | 只比较总字节/文件数量，同长度内容损坏、文件替换可能通过 | 逐文件 SHA-256、目录结构、链接目标校验，切换前再次检查写入变化 |
| 权限与跨盘复制 | `/COPY:DAT` 不保留访问权限；本机 Robocopy 复制安全信息失败时可能退出码为 0、目标为空 | 复制并核验 NTFS 访问权限，识别日志中的错误码；必要时用 .NET 复制、复验有效权限，保留子项继承关系，无法安全保留时停止 |
| 链接往返 | 迁回时不核对原路径指向；内部绝对链接或外部相对链接可能指向错误位置 | 核对记录中的链接目标，调整复制后链接，拒绝被替换的路径 |
| 清理失败 | 旧副本已部分删除仍可能被恢复为正式目录 | 明确提交点，确认可用的新目录后保留正式状态；清理失败单独报告和重试 |
| 中断恢复 | 迁回临时目录没有写入记录，恢复逻辑可能误判方向 | 持久化 restorePath，区分正向迁移和迁回，保留存在冲突的数据 |
| 操作并发 | 迁移、迁回、删除、重命名和退出可能相互打断 | 操作互斥；退出等待正在执行的事务和写入；启动恢复完成后开放 IPC |
| 历史记录 | 可删除仍在使用的迁移记录，丢失迁回入口 | 保留有效迁移和仍含恢复/清理路径的记录 |
| 路径保护 | 路径别名、设备路径、应用自身路径可能绕过检查；重命名可能覆盖已有文件 | 核验实际父目录和受保护位置，阻止覆盖已有目标 |
| 强删占用 | 只按命令行推测占用，漏掉真正持有文件的进程 | 增加 Windows Restart Manager 查询，显示检测限制 |
| 强删进程处理 | 未先尝试删除即结束进程；执行时可能杀掉未确认进程/子进程 | 先删除，失败后只处理已确认且身份未变的进程；持有进程句柄核对启动时间 |
| 强删链接/属性 | 递归 attrib 可能修改链接外部文件 | 移除递归 attrib，不遍历链接目标；验证删除结果 |
| 配置文件 | 读取失败直接覆盖为默认配置；损坏迁移项被静默丢弃 | 保留原文件并明确报错，不在丢失记录后继续写入 |
| 配置写入 | 写入/加密失败后内存仍显示成功，后续操作可能保存错误状态 | 串行、同步落盘后提交状态，失败不发布变更 |
| 设置界面 | 保存响应覆盖较新的草稿；旧 AI 请求覆盖新连接；语言切换重复初始化 | 合并保存期间新草稿，丢弃过期请求，避免重复初始化 |
| 迁移界面 | 完成一次迁移后无法再次执行；旧预检覆盖新路径；运行中可改路径 | 重置完成状态，绑定预检对象，执行期间锁定路径 |
| 强删界面 | 失败后继续使用已消费确认；权限错误被泛化提示覆盖 | 重新预检/确认，显示具体原因和扫描警告 |
| 卸载恢复 | 读取失败显示成没有记录；独立恢复进程可能并发写日志 | 显式错误与重试；保留单实例约束，恢复启动失败时停止卸载 |

## 为什么“强制删除”仍可能失败

旧实现确有漏检占用和错误处理问题，已修复。但 Windows 会拒绝删除未允许共享删除的打开文件，内存映射也可能阻止删除；管理员身份不等于解除所有文件锁。参见 [Microsoft DeleteFile 文档](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-deletefile)。

新的检测最多遍历 5000 项且不跟随链接。目录句柄、驱动锁、受保护服务、拒绝访问的 ACL、范围外的文件、预检后新启动的进程、后台持续重建目录仍可能导致失败。界面保留错误码和失败子路径，要求关闭占用/停止写入/检查权限后重新预检，不会结束未经确认的进程或越过系统路径保护。

## 删除失败后的操作指引（本次补充）

失败窗口按错误原因显示可执行的操作顺序，并明确提醒管理员权限无法解除所有文件锁、驱动占用或访问限制。

| 失败原因 | 界面提供的操作 |
| --- | --- |
| 文件占用 | 保存工作，完全退出关联应用及托盘程序，关闭资源管理器预览/相关终端；打开任务管理器，在“详细信息”核对上次预检的名称和 PID，只结束确认属于目标的普通应用 |
| 权限拒绝 | 未提权时说明如何从托盘退出并以管理员运行；已提权时不要求重复提权；定位文件，在“属性 → 安全 → 高级”检查当前账户有效访问权限，由所有者/管理员调整自己普通文件的删除/修改权限 |
| 后台重建目录 | 先暂停同步、下载、备份和自动更新任务，再退出关联应用 |
| 顽固占用、服务或驱动 | 展开说明，先正常重启，在关联应用启动前重试；服务自动启动或持续重建时使用系统/厂商卸载程序 |
| 普通残留文件仍无法删除 | 给出 Shift + 重启进入安全模式的完整步骤，提示加密设备先准备 BitLocker 恢复密钥，在安全模式使用资源管理器处理普通残留；仍拒绝访问时联系所有者/设备管理员/厂商 |
| 受保护路径 | 引导使用卸载或系统清理工具，不提供绕过路径保护的操作 |
| 迁移中的数据或并发操作 | 引导迁移历史恢复或等待当前操作完成 |
| 目标变化、过期确认或已不存在 | 核对实际路径、刷新结果，再重新预检和确认 |

窗口提供“定位文件”“复制路径”“打开任务管理器”“打开已安装的应用”和[微软安全模式说明](https://support.microsoft.com/en-us/windows/experience/startup-boot/windows-startup-settings)入口。系统工具只有用户点击才打开，不自动重启、更改权限或结束额外进程；辅助入口失败时保留原删除错误，并提示手动快捷键。底层仅接收两种固定工具标识，拒绝任意命令或路径。

删除失败后保留上次预检的权限与进程信息作为操作参考；重试必须获得新预检并重新勾选确认。错误码与实际失败子路径在“查看失败原因与路径”中完整保留。

增大指引字号，并修复两倍字号下英文标题被弹窗压缩后覆盖正文的问题；标题、底部按钮保留高度，长说明可在正文区域滚动。

## 迁移的适用范围

迁移要求可识别的 NTFS 源盘和目标盘，以保留权限、数据流与链接。WindowsApps、商店应用数据、系统目录和 CDriveShiftAI 自身目录被阻止。共享硬链接不能直接跨盘保持语义，验证会停止此类迁移。服务、驱动、DRM 和厂商更新器可能依赖特定安装方式；代码测试不能保证所有第三方应用支持目录迁移。迁移前仍须完全退出关联应用。

本次未读取到可用于复现某一真实应用损坏的现有迁移事务，不能据此宣称已恢复过去丢失的文件或修复所有厂商应用。自动恢复会保留有冲突或无法核验的数据副本。
