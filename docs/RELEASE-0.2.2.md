# CDriveShiftAI v0.2.2

本版修复自动更新启动确认的事件时序及失败恢复时的子进程占用。0.2.1 已撤回：现场升级虽然完成安装并打开了新版窗口，但启动确认漏掉了页面停止加载事件，随后错误触发超时；失败恢复又受到残留子进程占用影响。

## 自动安装与重新打开

- 补齐主页面停止加载后的状态检查，并在页面完成加载、窗口显示或恢复等事件返回后复核一次状态，解决窗口已经打开，却一直未确认更新成功、最终被误判为启动超时的问题。采用事件驱动，无持续轮询；仍需主页面加载完成、窗口可见且未最小化，才确认成功。
- 使用独立 Windows Job 跟踪本次更新启动的应用进程树。失败恢复前停止该进程树，等待文件占用释放后再恢复旧版，处理 Electron 子进程或索引器残留导致的 Windows `error 5`；不按进程名结束其他应用。成功后释放 Job 跟踪，应用继续运行。
- 保留更新助手工作目录隔离、安装器临时目录设置和应用数据保留；新版与恢复的旧版使用更新暂存目录之外的工作目录及长期存在的数据临时目录。
- 保留官方下载大小和 SHA-512 校验，以及真正启动失败时的旧版恢复流程。

## 受影响旧版本的升级方式

已安装的旧版本若仍携带存在问题的更新助手，可能需要从 [GitHub Releases](https://github.com/PuppetWen/CDriveShiftAI/releases) 下载本版 `CDriveShiftAI-x64.exe`，退出应用后在原安装目录覆盖安装一次，获取修复后的助手；不要先卸载或删除应用数据目录。便携版可退出后用本版便携包替换原可执行文件，并保留同目录的数据文件夹。

新包中的修复不会倒过来修改旧客户端已经启动的更新助手。此前本机现场升级已先做过旧助手引导修复，不能据此声称未经修补的旧客户端可以直接自动升级成功。

## 验证

- 4 个更新相关测试文件、33 项测试通过，包含新增的加载完成及窗口显示状态时序回归。
- 真实 Electron 43.2.0 加载生产主进程与完整页面的回归通过，覆盖正常显示、先加载后显示、加载失败、提前关闭、实际成功标记写入及暂存清理后窗口继续显示。
- 11 项 Rust 更新器测试通过。真实三层测试进程复现“只结束父进程仍有子孙进程持有独占文件锁”，随后验证 Job 终止整个测试进程树后可以恢复旧文件、数据哨兵保留，同名无关进程仍存活。
- 本地待发布便携包完成真实原生更新计划回归：旧目标文件版本 0.2.1，替换为 0.2.2；包内助手校验 SHA-512、启动新版并收到成功标记；新版主窗口显示，助手退出后继续运行，约 15 秒后按测试计时正常退出。更新后可执行文件哈希、数据哨兵、暂存目录和助手目录自动清理均通过。
- 上述便携测试直接使用本地原生更新计划，不启动旧版，也不涵盖官方下载、原始旧助手或安装版 NSIS 路径。此前官方便携下载验证针对 0.2.0，不能代替本版验证。本版真实 D 盘安装更新仍待单独核对。
